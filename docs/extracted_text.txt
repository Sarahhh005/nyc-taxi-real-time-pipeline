PROJECT OVERVIEW
What we built
A Big Data platform that takes NYC Yellow Taxi trip records, streams them the way live production traffic would arrive, cleans and aggregates them in flight, and stores the result where analysts can query it in milliseconds — fully automated and containerized.


Simulate real-time streaming

Clean & transform at scale

Analytics-ready storage
ClickHouse holds trip-level records for sub-second queries.


Automated orchestration
Airflow verifies infrastructure health and triggers the stream.


Modern, containerized stack
Every service runs isolated and reproducible via Docker Compose.

STEP 2 OF 6  —  EVENT STREAMING
Kafka — the real-time backbone








What it does
A Python producer reads NYC Taxi trip rows from the Parquet source and publishes each one as a JSON message to a Kafka topic — turning a static historical file into a live, continuous event stream that downstream consumers can subscribe to.

Topic
taxi-trips

Message format
JSON, one trip per record

Bootstrap server
localhost:9092
TRAFFIC MODES
The producer can simulate different demand levels

Peak
~0.05s delay ± 40%
Rush-hour message rate

Normal
~0.5s delay ± 30%
Typical daytime traffic

Off-peak
~2.0s delay ± 25%
Overnight, low-demand hours
06
STEP 3 OF 6  —  STREAM PROCESSING
Spark — cleaning and validating in flight






Spark Structured Streaming subscribes to the Kafka topic, parses each JSON message against a defined schema, casts every field to its proper type, and applies a set of data-quality rules before writing clean micro-batches to ClickHouse via JDBC.
TRANSFORMATIONS

1
Parse
Read raw Kafka JSON against a fixed 10-field schema.

2
Cast
Convert timestamps, ints and floats to their target types.

3
De-duplicate
Drop exact duplicate trip records.

4
Clean nulls
Drop rows missing pickup/dropoff time; fill missing passenger count.

VALIDATION FILTER
Only trips passing every rule reach ClickHouse

fare_amount ≥ 0

passenger_count ≤ 8

dropoff_datetime > pickup_datetime

pickup / dropoff zone IDs between 1 and 265

payment_type between 0 and 6

excludes zero-distance trips with fare > $10

STEP 4 OF 6  —  ANALYTICAL STORAGE
ClickHouse — built for instant queries








Why ClickHouse
A column-oriented analytical database purpose-built for aggregations over large volumes of event data — exactly the kind of scan-heavy queries a taxi-demand dashboard needs to run in milliseconds.
SETUP

Database
NYC_TAXI

Table

Engine

Ordered by

Write path

ANALYTICAL QUERIES
What Agents asks ClickHouse

Total trip volume
COUNT(*) across all trips

Average fare & tip
AVG(fare_amount), AVG(tip_amount)

Tip performance by zone
AVG(tip_amount) grouped by pickup_location_id

Demand over time
COUNT(*) grouped by minute-level pickup time
